# 02 · 版式与风格

## 一、9 套版式模板

版式写在 `engine/engine.js` 里，由 `content.json` 每镜的 `tpl` 字段选用。
以下坐标均为 1080×1920 画布下的**安全区 230–1560**（上下各留 230/360 给 HUD 与字幕）。

| tpl | 版式要点 | 关键字段 | 无插画时的母题 |
|---|---|---|---|
| `hook` | 两行大字标题 + 底部大插画 + 从下往上飘的"推销弹窗雨" | `title` `sub` `asset` `popups[[文案,色,横向位置,速度]]` | `ringStack` |
| `step` | 左上序号徽标 → 上部插画 → 中部大数字卡片（带彩色卡头）→ 底部条幅 | `badge` `asset` `card{title,sub,value,unit,note}` `ribbon` | `blockStack` |
| `chips` | 序号徽标 + 中部插画 + 两枚白色胶囊（底部一枚可带 ✓） | `badge` `asset` `chips[[文案,解说进度,左,上,色]]` | `togglePair` |
| `split` | 序号徽标 + 上部插画 + 左右分割费用条 + 斜纹高亮面板 + 金币入库 | `badge` `asset` `bar[左,右]` `panel{title,value}` | `halfDisc` |
| `bigNumber` | 序号徽标 + 顶部保额卡（数字滚动）+ 右侧插画 + 左侧三枚标签 + 左下「✗ + 要否定的做法」徽标（`warn` 选填，不填就不画） | `badge` `value{label,number,unit,note}` `asset` `tags[[文案,解说进度,y]]` `warn`（选填） | `barRise` |
| `pitfalls` | 大标题 + 三张红叉卡片，逐张横向展开并带抖动 | `title` `items[[文案,解说进度]]` | —— 本来就不放插画 |
| `coins` | 序号徽标 + 中部插画 + 三枚金币下落 + 右上角提示胶囊 | `badge` `asset` `note` | `barRise` |
| `funnel` | 标题 + 五根高低不等的流程柱（末根虚线框）+ 顶部箭头连接线 + 底部链条文案 | `title` `sub` `steps[[名,色,高度]]` `chain` | —— 本来就不放插画 |
| `outro` | 独立暖色/深色渐变底 + 主副标题 + 插画 + 关注胶囊 + 免责声明 | `title` `sub` `asset` `cta` | `ringStack` |

### 插画是可选的

七个带 `asset` 的版式都有一条**无插画分支**：把 `asset` 键整个删掉，版式会在同一个位置画一个几何母题。
共同的包络是 `cx/cy/w` 不变、高按 `0.72w`（与 `assetH` 的兜底一致），而且**共用同一个入场进度 `p`**，
所以选不选插画不会挪动任何拍点，也不会改变安全区结论。

- `asset` 要么填 `assets` 里的合法素材名，要么**整键删掉**。填空字符串 `""` 会报错（不在 `assets` 里）。
- `assets` 也可以整份省略或写成 `[]`，那就是全片无插画。
- 配色只用 `CL(accent)` + `C.ink2` + `C.card`，这三者三套皮肤都过了对比度；母题一律平涂，**禁用 `shadowBlur`**。
- 母题自己会把包络通过 `gbox()` 报给 `scripts/layout_probe.js`（见 `05-校验方法.md`），否则无插画版式的越界永远查不出来。

**通用元素**（所有版式自动带）
- 顶部 HUD：进度条 + 品牌胶囊（`meta.brand`）
- 底部字幕气泡：由 `narration` 自动分句，宽度自适应，上下淡入淡出
- 分镜转场：按**进入镜的 tpl** 查表选一种（溶解 / 横滑 / 上滑 / 擦除 / 横带），时长由 `meta.pace.transition` 决定（默认 0.45s）

> **版式与位置是解耦的。** 每个场景函数用 `SCN(i)` 取自己那一镜的内容（`i` 由渲染入口传进来），
> 所以分镜顺序可以自由排、同一个版式也能用多次。**不要**在场景函数里写 `SCN(0)`、`SCN(3)` 这种固定下标——
> 早先就是这么写的，一旦重排分镜，版式会挑对被画的却是别一镜的内容，且不报错。

### 字幕几何与安全区

字幕气泡的尺寸和位置集中在 `engine.js` 顶部的 `SUB` 对象里（字号、每行字数、行高、内边距、底边、淡入时长）。
`SUB_TOP` / `SUB_AVOID` 由它**推导**出来——scene1 的弹窗雨靠 `SUB_AVOID` 决定在哪一段纵向范围内淡出避让。

**改字幕位置只改 `SUB.bottom` 一处**，避让带会自动跟着走。以前两处各写了一份魔数（气泡几何一份、
避让带一份），改一处必然让另一半失配，弹窗雨就会重新糊在字幕上。

## 二、节拍模型（动画挂在配音上）

### 为什么不是秒

每镜时长是 `dur = 0.30(LEAD) + 本镜配音实测时长 + 0.36(TAIL)`，**内容驱动的变量**。
早期所有入场动画的关键帧都写成"相对场景起点的绝对秒数"，于是配音一长，元素落位后画面就冻着不动——
实测一版 62.57s 的成片里，约 18.7s（≈30% 片长）是静帧，这是"看着廉价"的主要来源，不是美术问题。

现在关键帧一律用**"解说进行到几成"**（0–1）表达，由四个辅助函数换算成秒（`engine/engine.js`）：

| 函数 | 含义 |
|---|---|
| `beats(i)` | 取第 i 镜的 `lead / sd(配音时长) / dur` |
| `bs(i, f, len)` | 解说进行到 `f` 处的场景内秒数；传 `len` 会封顶到"场景结束前 `len+0.06`s"，保证动画播得完 |
| `bseg(t, i, f, len)` | 出场进度：解说 `f` 处开始、历时 `len` 秒 |
| `lseg(t, i, len)` | lead-in 进度：在解说开始**之前**落位（徽标、大标题走这条） |

三个内容字段的时间项因此从「秒」改成了「解说进度 0–1」：

| 字段 | 含义 |
|---|---|
| `chips[[文案, 解说进度, 左, 上, 色]]` | 胶囊逐枚落位 |
| `tags[[文案, 解说进度, y]]` | 侧标签逐枚落位 |
| `items[[文案, 解说进度]]` | 红叉卡片逐张落位 |

其余时间字段语义不变：`popups[3]` 是速度倍率，`steps[2]` 是柱高。

### 约定

- 徽标 / 大标题用 `lseg`，在 LEAD 期间落位
- 内容元素用 `bseg` 铺满解说窗口，总结/警示落在 `f≈0.76–0.85`（不钉 1.0，留出可读时间）
- **不要**在场景函数里用 `t` 直接算绝对时刻；一律经 `bseg`/`bs`

### 存活期微动

入场播完之后画面不再静止：场景级摄影机漂移（`sceneCam`，平移 ≤6px、缩放 ≤1.004）、
插画缓慢浮动（`drawAsset` 内 ±4px）、主卡片落位呼吸（`settle`，幅度 1.2%）。
**漂移幅度被安全区余量锁死**：最贴边的 `stepBadge` 顶边 y=250，全幅漂移下到 241，距安全区上界 230 只剩 11px；
调大 `sceneCam` 之前先重算这个余量。全屏底色已 overscan 24px，否则漂移会露出未绘制边缘。

改动是否有效用 `node scripts/motion_check.js <frames_dir>` 验证。

### 动效词汇

**入场按"重量"取时长和曲线**，不再各处手写。`engine.js` 里的 `WEIGHT` 表：

| 重量 | 时长 | 曲线 | 用在哪 |
|---|---|---|---|
| `micro` | 0.26s | `easeOutBack` | 小胶囊、标签、小色块 |
| `small` | 0.42s | `easeOutQuart` | 条幅、note、连接线、金币 |
| `mid` | 0.60s | `easeOutQuint` | 卡片、面板、费用条 |
| `heavy` | 0.90s | `easeOutExpo` | 大标题、主插画、funnel 柱 |

场景里一律写 `enter(t, i, f, 'mid')`——语义就是原来的 `easeOutCubic(bseg(t,i,f,0.60))`，
即"解说进行到 `f` 处开始"，只是时长与曲线集中到了这张表里。

> **重量 × f 规则（会咬人）**：`bs()` 会把起点封顶到 `dur − len − 0.06`，把元素**往前挪**，于是"抢拍"。
> 咬人的条件是 `len > 0.30 + sd·(1−f)`（代入 tail=0.36）。所以 **`heavy` 只能用在 `lseg` 或 `f ≤ 0.4` 的早段元素上；
> `f ≥ 0.6` 的尾部元素最多用 `mid`**。反例：短镜 `sd≈2.3`、`f=0.8` 时阈值是 `0.76 < 0.90`，heavy 一定被抢拍。

**离场**：`withExit(ctx, t, i, len, body)` 把一镜的内容整体包起来，收场钟是 `egress`——
**锚在场景边界而不是解说拍点**，不经过 `bs()`，所以永不参与封顶，加它不会移动任何入场拍点。
窗口长度由 `exitLen(i)` 给：

```js
min(clamp(dur * 0.18, 0.35, 0.80), max(0.30, tail * 0.45))
```

前一半是原来的公式。**后一半是后补的上限，别删**：只按 `dur*0.18` 算，窗口常有 0.55–0.80s，
比默认 `tail`（0.36s）还长，离场必然啃进解说里——实测四镜分别在解说念完**前**
0.20 / 0.25 / 0.33 / 0.27 秒就开始撤场。而几个"点睛"元素的拍点排在解说 76%–85% 处、
落位动画自己还要 0.55–0.60s，正好被撤场切掉：大数字镜的红杠划到一半、funnel 的连接线刚连上，
画面已经在滑走了（s3 的链条比离场晚了 0.08s——那一镜全程没有一帧是停稳的）。
钉上 `tail * 0.45` 之后，每个点睛元素落位后至少还有约 0.3–0.4s 静止 + 0.54s 走位（tail=1.20 时）。

- **`bgBase` 必须排除在 `withExit` 之外**：背景一旦淡出，转场的前半帧会露出画布底色。
- 横向推出（`translate(-x*120, 0)`）而不是缩放——缩放会顶破安全区（余量只剩 11px）。
- **结尾镜不包 `withExit`**：散场不该清场。

**转场**：按进入镜的 `tpl` 查 `XN` 表，`dissolve` / `slideR` / `slideL` / `slideUp` / `wipeL` / `band`。
表默认以 `dissolve` 为主——转场种类用多了会显得吵。`TRANS`（`PACE.transition`）没改，所以 `sync_check.py` 不受影响。

窗口骑在镜边界上（`[start − TRANS/2, start + TRANS/2]`），所以要**直接扫边界**、不能拿 `sceneIndexAt(t)` 当判据——
它在边界之前返回的是上一镜，`t >= start − half` 于是只在边界之后才成立，窗口被砍成半段、`p` 从 0.5 起步。
**`TRANS = 0` 就是硬切**：窗口为空，永远不 `blended`（`p` 也就不会去算 0/0）。想要硬切不必改引擎，写配置就行。
`layout_probe.js` 挂钩的是 `drawImage` 的**原始参数**，看不到 `ctx` 变换矩阵，**转场期间的几何它验证不了**，安全余量必须手算。

**氛围层**：`renderFrame` 里在**合成之后、`drawHud`/`drawSubtitle` 之前**画一次（转场时也只画一次），
顺序是暗角 → 撞击闪光 → 颗粒。放在 HUD 和字幕之前是刻意的：否则暗角会把顶部 HUD 和底部字幕一起压暗。

- 暗角预渲染到离屏画布，每帧只 `drawImage` 一次。直接求值全屏径向渐变实测 2.67ms/帧，预渲染后 0.22ms/帧，画面逐像素相同。
- 闪光是把峰值压得很低的撞击（`a² × 0.12`，时长 `PACE.flash`，默认 0.11s），不是给画面蒙雾；用纯色填充，不碰 `shadowBlur`。
  相位锚在 `sc.start + lead`。但 `lead` 只是主体**开始**落位，主体自己还要走 0.6–0.7s 才到位——
  所以峰值那一帧台上仍近乎空的（实测 s1→s2：背景区亮度 37.1 → 51.8，+40%，画面上只有一枚徽标），
  读起来更像「屏幕闪了一下」而不是「撞了一下」。**`PACE.flash = 0` 关掉它**，配合 `transition: 0` 就是最干净的换镜。
- 颗粒用固定种子的 LCG 造一张 256×256 瓦片全片复用（**绝不能用 `Math.random`**），且瓦片放大 4 倍再铺：
  细噪点是高频，x264 要在 DCT 里逐块花码率，`GS=1` 时体积 9.14MB、`GS=4` 只要 5.72MB。合成模式是 `source-over` 而不是 `overlay`
  （深底上白噪声本来就是"加光"，`overlay` 的对称明暗会把能量自己对消掉：同样 alpha 下 `overlay` 平均差 0.30、看不见却要 34.3ms/帧，
  `source-over` 平均差 2.4、看得见且只要 11.1ms/帧）。

**节奏强度（`energy`）**：每镜可选 `high`（默认）/ `low`。`low` 是给过渡镜的——不撞击闪光、不横抖、入场曲线换成最平的 `easeOutCubic`。
动效的价值全在对比，全片都 `high` 等于全片都没有重音。不写就是 `high`，老内容一行都不用改。

### 背景图层

`bgBase` 拆成了底 + 四个可选图层，由两个 token 的 alpha 开关：`gridInk`（点阵网格 + 同心圆脉冲）、
`scanInk`（扫描线 + 数据流）。**token 全透明时 `alphaOf()` 返回 0、函数直接 `return`**，
所以 warm / dark 上这几层既不画也不占时间是零成本的 no-op，只有 tech 打开。
所有图层都由 `t` 推导，没有 `Math.random`。

**发光**：`glowWrap(ctx, color, fn)` 先带 `shadowBlur` 画一遍当光晕、再平涂一遍压实（只画一遍主体会被光晕糊掉）。
`C.glow ≤ 1.05` 时直接平涂，所以 warm 零成本。只用于大数字 / CTA 胶囊 / 序号圆这几处小目标——
`shadowBlur` 是全案唯一被点名很贵的调用，**别往全屏元素上套**。

### 节奏（`meta.pace`）

每镜时长 `dur = lead + 配音实测时长 + tail`，这里的 `lead` / `tail` 以及末镜的 `lastTail`、
转场时长 `transition`、撞击闪光 `flash` 都可以在 `content/<x>.json` 的 `meta.pace` 里改（单位秒，不写就用默认）。
它一路流到 `build_content.py`（算时间轴）→ `src/timeline.js` 的 `window.PACE` → `engine.js` 的 `TRANS` / `FLASH`。

**这是唯一一处跨 JS / Python 的节奏常量，所以只有一个入口。** 改 `lead`/`tail` 会同步改变每镜时长、
总帧数和成片长度；`beats()` 从时间轴反推留白，所以节拍、安全区、动画封顶都会自动跟着走，不需要另改。
`transition` / `flash` 反过来——它们**只改画面、不改时长**，所以调它们不用重跑时间轴（但仍要重渲染）。

放宽 `lead` 会让徽标和大标题有更长的落位时间；收紧则更利落。`transition` 超过 `lead + tail` 时
相邻两镜会长时间重叠，别调过头。

**硬切（`transition: 0`）为什么是干净的**：`withExit` 收在 `dur − 0.06`，下一镜的 `lead` 里只有徽标/大标题在落位，
所以镜边界两侧本来就是「近乎空的背景」——实测 s1→s2 的硬切帧间差只有 1.14（镜内中位数 0.5–2），等于看不见。
唯一例外是进 `outro`：它不挂 `withExit`、背景是另一套更亮的渐变、标题也不淡入，所以那一刀会有一次约 +26% 的
整体提亮（帧间差 28.5，其余三刀是 2.3 / 5.4 / 1.1）。画面同时全变了，读起来是「换了个亮镜头」而不是「闪了一下」，
不需要处理；真想让这一刀也柔下来，就把 `transition` 调回 0.3 左右，别去动 `lead`/`tail`。

### 帧率（`meta.fps`）

`content/<x>.json` 的 `meta.fps` 控制整片帧率，默认 **30**。它一路流到
`build_content.py`（算帧数）→ `src/timeline.js` → `engine.js` → `render_frames.js`（逐帧步长）→
`encode.py`（`-framerate` / `-r` / 关键帧间隔）。**这几处必须读同一个值**——任何一处写死，
帧数和播放速率就对不上，音画会直接错位。

各档位的取舍，按本引擎里实际存在的运动频率算：

| fps | 帧数（62.5s） | 抖动 4.8Hz 每周期采样 | 评价 |
|---|---|---|---|
| 30 | 1877 | 6.3 点 | **默认**。平台标准，抖动和弹窗雨最好看 |
| 24 | 1501 | 5.0 点 | 可接受的下限，省 20% 渲染与体积 |
| 20 | 1250 | 4.2 点 | 抖动会闪 |
| 15 | 938 | 3.1 点 | 明显卡顿，不要用 |

- 其余动效（摄影机漂移 0.02–0.06Hz、插画浮动 0.28Hz、落位呼吸 0.18Hz、入场 0.4–1.8Hz）
  在 24fps 下都远远够采样，**帧率的下限是被抖动这一项钉死的**。
- 60fps 没有收益：这片子里没有高速运动。
- 25fps 是 PAL 惯例，这里没有优势。

**降低帧率省的是渲染时间和文件体积，不是 token。** 渲染/编码是本地 Playwright + ffmpeg，
完全不经过模型。token 只花在"把静帧读进上下文"的时候，和帧率无关。

## 三、风格层（皮肤）

`styles/<name>.json` 定义两件事：

1. `theme` —— 7 个强调色 + 背景/正文/次要文字色
2. `tokens` —— 卡片、字幕、HUD、金币等**结构性色板**

`content.json` 的 `meta.style` 选皮肤；`content.json` 里若还写了 `theme`，会**覆盖**皮肤的同名项（做单片微调用）。

### token 一览

| token | 作用 | warm | dark |
|---|---|---|---|
| `card` | 卡片/胶囊底色 | `#FFFFFF` | `rgba(26,37,58,0.92)` |
| `onAccent` | 强调色块上的文字 | `#FFFFFF` | `#0B1220` |
| `soft` | 卡片内浅色圆底（红叉等） | `#FFECEC` | `rgba(255,92,122,0.16)` |
| `headFrom` | 卡片头部渐变起始色 | `#FF9E52` | `#FFC98A` |
| `sheen` | 卡片装饰高光 | `rgba(255,255,255,0.22)` | `rgba(255,255,255,0.07)` |
| `seal` | 流程柱渐变末端 | `rgba(255,255,255,0.75)` | `rgba(11,18,32,0.55)` |
| `dash` | 虚线框柱底色 | `#E7E2F7` | `rgba(169,140,255,0.14)` |
| `coin` / `coinEdge` / `coinInk` | 金币三色 | 金/深金/棕 | 亮金/暗金/深棕 |
| `hudTrack` / `hudChip` | HUD 进度槽 / 品牌胶囊 | 浅灰 / 白 | 半透明白 |
| `subBg` / `subInk` / `subShadow` | 字幕气泡三色 | 白 / 深棕 / 暖灰影 | 深蓝玻璃 / 浅蓝 / 黑影 |
| `lineA` | 斜纹线 | 蓝 30% | 蓝 20% |
| `splitLeft` / `splitRight` | 费用条左右两段 | 薄荷/橙 85% | 亮薄荷/亮橙 80% |
| `walletDot` | 钱包装饰点 | `#FFE0C2` | 同 |
| `outroBg1/2/3` / `outroGlow` | 结尾渐变三停 + 光斑 | 暖米黄 | 深蓝 |
| `shadow` | 投影基色 | 暖棕 20% | 纯黑 55% |
| `glow` | 背景光斑强度倍数 | `1` | `2.4` |
| `vignette` | 暗角边缘色 | 暖棕 20% | 纯黑 45% |
| `grain` | 颗粒强度（0 = 关闭） | `0.035` | `0.022` |
| `gridInk` | 点阵网格 + 同心圆（透明 = 关） | 透明 | 透明 |
| `scanInk` | 扫描线 + 数据流（透明 = 关） | 透明 | 透明 |
| `fontNum` | 数字字体栈 | 同 `FONT` | 同 `FONT` |

> `grain` 在深底皮肤下要明显低于浅底：白噪声在深底最显，容易显脏。而且噪声会破坏帧间压缩、抬高成片体积——
> **这是全案最该实测的一项**。
>
> **tech（深空科技风）** 是第三个皮肤，差异只在 token：更深的底（`bg #060A14`）、霓虹强调色、`glow 3`、
> `vignette 0.50`，并且**打开 `gridInk` / `scanInk`**（唯一会画背景图层的皮肤），
> `fontNum` 换成等宽栈（数字对齐更硬、更像仪表盘）。它必须过 `python3 scripts/check_contrast.py tech` 且 `不达标: 0`——
> 最紧的一项是 `onAccent` 要对**每一个**强调色都 ≥4.5:1，所以搭配必须是"极深 onAccent + 亮强调色"。

### 加一个新风格

1. 复制 `styles/warm.json` → `styles/<新名>.json`
2. 改 `theme` 和 `tokens`（不改 `engine.js`）
3. `python scripts\check_contrast.py <新名>` 确认没有读不清的组合
4. `content.json` 的 `meta.style` 改成新名，重跑管线

> **加色 token 时要同时改三处**：`engine.js` 的 `C` 对象（默认值）、`styles/*.json`（各皮肤的取值）、
> `content/schema.json` 的 `colors.themeKeys`（校验用）。前两处不同步不会报错，只是颜色不对；
> **第三处不同步会被 `build_content.py` 直接点名**——它会拿 `engine.js` 的 `C` 去核对 schema。
> 名字打错的 token 以前会被引擎的 `if (k in C)` 静默丢掉，现在校验会拦。

### 换风格家族（需要动引擎）

如果新风格不是"换色"而是"换表达"——比如实拍 B-roll 背景、白板手绘、3D 等：
新建 `engine/<family>.js`，复用 `build_content.py` / `render_frames.js` / `encode.py` 不变，
只把 `RENDER_HTML` 指向新的入口 html。管线其余部分完全共用。
