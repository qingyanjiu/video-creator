# 04 · 环境与踩坑记录

这一份是实战踩出来的，照着改能省几小时。

## 1. edge-tts 返回 403 / 连接被拒

**症状**：`edge_tts.Communicate(...).save()` 抛 403 或 WebSocket 握手失败。

**原因**：微软把语音合成端点迁到了新域名，`edge-tts` 旧版仍打老地址。

**修复**（`scripts/build_content.py` 里已内置）：

```python
import edge_tts, edge_tts.communicate as C, edge_tts.constants as K
NEW_WSS = ("wss://api.msedgeservices.com/tts/cognitiveservices/websocket/v1"
           f"?Ocp-Apim-Subscription-Key={K.TRUSTED_CLIENT_TOKEN}")
K.WSS_URL = NEW_WSS
C.WSS_URL = NEW_WSS
```

**附带**：偶发 429 是限流，退避重试即可（脚本已实现 6 次、间隔 4/8/12… 秒）。
中文女声推荐 `zh-CN-XiaoxiaoNeural`，语速 `+8%` 在科普口播里比较自然。

## 2. 渲染出的画面上插画是空白

**原因**：图片是异步加载的，Playwright 截第一帧时 SVG 还没 decode 完。

**修复**：`engine.js` 里维护 `window.__assetsReady`，全部 `onload`/`onerror` 后置 `true`；
`render_frames.js` 在渲染前 `waitForFunction('window.__assetsReady === true')`。

> 只加状态位还不够——**渲染脚本必须真的去等它**。这是最容易漏的一步。

## 3. `file://` 页面加载本地 SVG

同目录/上级目录的相对路径 `<img src="...">` 在 `file://` 页面下**可以**加载（Chrome/Edge 允许图片子资源），
但 `fetch()` / `XHR` 会被 CORS 拦。所以素材统一走 `<img>`：

```js
const im = new Image();
im.src = 'assets/xxx.svg';   // 相对 render.html 的路径
```

`content.json` 里用 `meta.assetBase` 控制素材根路径，方便把素材挪到别处。

## 4. Canvas 里画 SVG 的坑

- `drawImage` 之前必须等 `naturalWidth > 0`，否则静默什么都不画
- 缩放后线条会变细，别把插画放得太小（本项目最小宽度 390px @1080 宽画布）
- `globalAlpha` 不要用在高频循环里的未复位路径上；本项目统一 `ctx.save()/restore()`

## 5. 中文字体

Canvas 不会自动 fallback，字体名要写全：

```js
const FONT = '"Microsoft YaHei UI","Microsoft YaHei","PingFang SC","Noto Sans SC",sans-serif';
```

写好后**必须 OCR 校验一遍**——字体缺失时 canvas 会画成豆腐块（□□□），肉眼看截图容易漏。

## 6. 逐帧渲染慢

- 1876 帧（62.5s @30fps）约 3.5 分钟，属正常
- **迭代期别全量渲**：用 `preview` 模式抽 5–10 个时间点，只在最后全量
- 别用 `page.screenshot({clip})` 分块拼，一次全画布更稳
- PNG 体积大（约 640MB/1876 帧），磁盘留够 2GB

## 7. 音画同步怎么保证

不要靠肉眼对。做法是**用音频实测时长反推画面时间轴**：

1. TTS 生成后立刻用 ffprobe 读真实时长
2. `build_content.py` 用该时长排 `start / speechStart / dur`
3. 字幕按 `speechDur` 按字数比例切分
4. 出片后用 `scripts/sync_check.py` 复验每段起音点

## 8. Windows 命令行与环境变量

- 一条命令字符串过长会被拒（Windows 有长度上限），长脚本分块写文件
- 用 `;` 在一行里串多个 node/python 调用容易出问题，分开执行
- 路径含中文时，PowerShell 控制台回显可能乱码，但**文件本身是 UTF-8，不影响结果**

## 9. `No module named 'imageio_ffmpeg'`

**症状**：跑 `scripts\encode.py` / `build_content.py` 时 Python 报
`No module named 'imageio_ffmpeg'`（或 `'edge_tts'`）。

**原因**：依赖装在了别处（比如临时目录），没进当前 Python 的 `sys.path`。

**修复**：一条命令（注意前面那个点，点源才会作用于当前终端）：

```powershell
. .\setenv.ps1
```

它按 `-PythonPath` → 项目内 `deps\pylibs` → 已设的 `PYTHONPATH` → 常见缓存目录 的顺序探测，
并**真的 `import edge_tts, imageio_ffmpeg, numpy` 验证一次**，通过才留下 `$env:PYTHONPATH`。
Node 侧（`playwright` / `sharp`）同理设 `$env:NODE_PATH`。
脚本最后会打印"可以开工了"或标红缺哪个依赖。

想一劳永逸，一句把依赖装进项目（`deps\` 已 gitignore），之后不用再配任何环境变量：

```powershell
.\install_deps.ps1                                             # Python + Node + Edge 驱动
.\install_deps.ps1 -DryRun                                     # 只打印要跑的命令，不真装
.\install_deps.ps1 -PipIndexUrl https://pypi.tuna.tsinghua.edu.cn/simple
.\install_deps.ps1 -NpmRegistry https://registry.npmmirror.com
```

它做的就是 `pip install --target deps\pylibs ...` + `npm install --prefix deps ...` +
`playwright install msedge`（只下 Edge 一套，跳过 playwright 默认那几套浏览器）。

也可以完全不管环境变量：`.\run.ps1` 检测到 `PYTHONPATH` / `NODE_PATH` 没配，
会自动点源同目录的 `setenv.ps1` 一次。
