# 05 · 校验方法

写完一版别急着交付。下面这些脚本覆盖了五类最容易翻车的问题：**看不清、盖住了、音画不同步、改坏了、画面冻住了**。

跑任何渲染之前，`build_content.py` 已经先挡了一层**内容校验**。

## 0. 内容校验（`build_content.py` 内置）

配置面写在 `content/schema.json`，`build_content.py` 按它逐字段校验，一次列全所有问题再退出：

```powershell
python scripts\build_content.py content\child-insurance.json
# 通过：校验通过：9 镜，7 个插画
# 失败：content 校验失败（content/child-insurance.json）：
#         scenes[1].asset 没有这个插画：'medcine'（assets 里只有 doctor / fatherhood / medicine …）
```

它挡的是**以前会静默画错**的那一类：`tpl` 拼错（悄悄变成钩子镜）、`asset` 名打错（那镜没插画）、
`accent` 写了个不存在的色名（canvas 忽略，元素变默认色）、色键拼错（引擎的 `if (k in C)` 直接丢掉）、
必填字段漏了、数组项数不对、`chips/tags/items` 的时间项写成了秒。

三个相关的约定：

- **`meta.size` 不存在。** 画布固定 1080×1920，九套版式都按这个尺寸手调绝对坐标；写 `size` 会报错。
- **schema 必须与引擎同步。** `colors.themeKeys` 和 `engine.js` 的 `C` 对象不一致时直接报错——
  加色 token 时两边都要加。
- **`styles/*.json` 的色键也过校验。** 皮肤里写错的键以前会被引擎静默忽略，现在会被点名。

## 1. 音画同步 `sync_check.py`

对每段解说，比较 `speechStart` 前 0.55s 静音窗与 `speechStart` 后 0.55s 的 RMS 能量比。
比值 > 4 说明该处确实起音了。

```powershell
python scripts\sync_check.py
```

期望输出：9 行全部 `ratio > 4`，最后 `RESULT: PASS`，且 `A/V length delta < 0.1s`。

## 2. 布局越界 / 遮挡 `layout_probe.js`

在页面里挂钩 `CanvasRenderingContext2D.prototype.fillText` 和 `drawImage`，
逐帧记录**所有文本的 bbox** 和**插画矩形**，再算交集。

```powershell
node scripts\layout_probe.js '[1.5,10.3,20.0,28.0,45.5,58.5]'
```

关注三种输出：
- 插画行末尾出现 `<<< OUT-OF-BAND` → 越出安全区（y 应落在 230–1560）
- `over text: ... ov=数字` → 插画盖住了文字
- 文本坐标出现**负数** → 该文本在 `translate/rotate` 的局部坐标里，属正常，忽略

> **无插画版式要靠 `__geomBox` 钩子才看得见。** 几何母题一次 `drawImage` 都不发，
> probe 只认 `drawImage`，所以不补钩子的话无插画版式的越界**永远是假绿**。
> 引擎侧每个母题开头调一次 `gbox(x, y, w, h, tag, a)`，probe 侧把它转成 `nat='geom:<母题名>'` 的 img 记录，
> 于是现有的 `o.w < 1000 && o.nat !== 'canvas'` 过滤器会自动放行，OUT-OF-BAND 与遮挡判读逻辑一行都不用改。
> 输出里看到 `IMG nov=geom:halfDisc` 就说明钩子生效了。

## 3. 配色可读性 `check_contrast.py`

按皮肤 JSON 计算 WCAG 对比度，沿用各元素的真实字号/字重：

```powershell
python scripts\check_contrast.py warm
python scripts\check_contrast.py dark
python scripts\check_contrast.py tech
```

阈值：正文 4.5:1，大字/强调 3.0:1。

**新皮肤（`tech`）的硬门槛是 `不达标: 0`**，加皮肤时别放过。最紧的一项不是强调色，而是
`onAccent` 要对**每一个**强调色都 ≥4.5:1——所以搭配必须是"极深 `onAccent` + 亮强调色"。

已知 `warm` 皮肤的强调色文字（橙/薄荷/蓝）压在白卡片上约 2.2–2.5:1，`不达标: 14`，
因为字号是 40–96px 加粗，实际可读；若要严格达标就把 `card` 调成浅灰或把强调色压深。
**这是历史遗留、不是新引入的**，warm 是已发布成片的皮肤，改动它要单独评估。

## 4. 逐像素回归 `diff_frames.js`

重构引擎、改皮肤、换字体之后，**必须**证明"只是换了实现，没有偷偷改画面"。

```powershell
node scripts\diff_frames.js out\frames_new out\frames_baseline 5
```

输出 `worst single-channel delta: 0` 即为完全一致。
本项目做引擎重构时用这招验过 376 帧，全部 0 差异。

## 5. 成片文字 OCR `ocr_all.js`

从**编码后的 MP4** 抽帧再 OCR，能抓出：字体缺失（豆腐块）、字幕裁切、文案错位。

```powershell
python scripts\verify.py                       # 抽 9 张关键帧到 verify_frames/
node scripts\ocr_all.js verify_frames
```

OCR 结果里出现成片插画的线条噪声是正常的；只要**每一镜的目标文案都能读出来**即可。

## 6. 素材完整性 `probe_assets.js` / `frame_stats.js`

- `probe_assets.js`：栅格化 SVG，统计 ink 覆盖率、bbox、主色——确认素材不是空图
- `frame_stats.js`：在成片帧的插画区域内统计"非背景像素占比"——确认编码后插画还在

正常区间：插画区填充率 **19%–57%**。接近 0% 说明素材没加载出来。

## 7. 画面动能量 `motion_check.js`

前面六个脚本都抓不到"元素落位后画面就冻住了"——而这个恰是"看着廉价"最常见的来源。

```powershell
node scripts\motion_check.js out\frames
node scripts\motion_check.js out\frames_v2
```

对每一镜取两段窗口抽帧，缩到 108×112 灰度图后算相邻帧的平均绝对像素差（0–255 灰阶）：

- **尾部窗口** `[dur-1.60, dur-0.25]`——入场动画早已播完，这里才看得见"落位后还有没有在动"
- **前段窗口** `[0.15*dur, 0.15*dur+0.9]`——参考值，入场期本来就该有大动作

看**尾部窗口**这一列：`< 0.15`（脚本里的 `MIN_TAIL` 常量）会标 `← 尾部基本静止`。
判读要看**相对基线的变化**，不要看是否为零——背景光斑一直缓动，全片差分不会是 0。

脚本已裁掉 HUD(y<230) 和字幕带(y>1250)。**这一步不能省**：字幕每换一行都是一次巨大的整块像素变化，
不裁的话"元素冻住、只有字幕在走"会被算成高分，正好把要抓的问题盖掉。

## 推荐顺序

```
改内容/皮肤
  → build_content.py
  → render_frames.js preview  →  layout_probe.js + check_contrast.py
  → render_frames.js png
  → encode.py
  → verify.py + sync_check.py + ocr_all.js
  → (若动过引擎) diff_frames.js 对基线；若改的是动效，diff 不为 0 是预期的，
     改用 motion_check.js 对新旧两版目录，确认尾部动能量确实上升
```
